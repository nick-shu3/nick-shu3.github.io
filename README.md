## 🤖 生成AIを活用した制作

この作品集では、生成AIをゲーム・Webツール制作に活用しています。

AIにすべてを任せるのではなく、

1. アイデアを考える
2. AIと相談しながら実装する
3. 実際に自分で遊ぶ
4. 違和感や問題点を見つける
5. 修正する
6. テストして公開する

という流れで制作しています。

ゲーム制作を始めて感じたのは、

> 「作る」ことと「面白くする」ことは別。

ということでした。

生成AIによって実装のスピードは大きく上がりましたが、ゲームとして面白いか、操作して気持ちいいか、初めて遊ぶ人にも分かるか、といった部分は実際にプレイしながら調整しています。

## 📁 リポジトリ構成

| 場所 | 内容 |
| --- | --- |
| `index.html` | GitHub Pages公開用トップページ |
| `docs/index.html` | 作品集トップページ |
| `docs/style.css` | 作品集のスタイル |
| `docs/catalog.js` | 作品一覧・カテゴリ切り替え |
| `docs/assets/` | 作品集で使用する画像 |
| `docs/games/kagi-to-tobira/` | カギとトビラ |
| `docs/games/squad-front/` | SQUAD FRONT |
| `.github/workflows/pages.yml` | 自動テスト・公開関連 |
| `tests/` | 公開ファイル・ゲームロジックのテスト |

トップページを変更する場合は `docs/index.html` と公開用 `index.html` の同期が必要です。

テストによって両者の整合性も確認しています。

## 🧪 テスト

Node.jsが利用できる環境では、リポジトリのルートから以下のテストを実行できます。

```sh
node tests/release.cjs
node tests/squad.cjs
node tests/kagi.cjs
```

主に以下を確認しています。

- 公開用ファイルの構成
- リンク切れ
- 公開範囲
- カギとトビラ第1章・全10階の攻略可能性
- SQUAD FRONTの勝敗処理
- 強化処理
- ゲームロジック

スマートフォンでの表示・操作感、音声、画像保存などについては実機でも確認しています。

## 💻 ローカルで実行する

Python 3が利用できる環境では、リポジトリのルートから以下を実行します。

```sh
python3 -m http.server 8000 --directory docs
```

その後、ブラウザで以下を開きます。


## 🚀 公開フロー

公開中の `main` ブランチを直接変更するのではなく、基本的に以下の流れで更新します。

```text
変更
 ↓
ブランチ作成
 ↓
コミット
 ↓
Push
 ↓
Pull Request
 ↓
GitHub Actionsによる自動チェック
 ↓
Merge
 ↓
GitHub Pagesへ反映
```

公開前に自動テストを通すことで、ゲームや作品集を更新した際の意図しない破損を防ぎます。

## 🔒 セキュリティとプライバシー

公開サイトでは、必要以上に外部サービスへ接続しない構成を基本としています。

Content Security Policy（CSP）を設定し、ブラウザから読み込めるリソースや通信先を制限しています。

ゲームの進行状況や記録は、対応する作品ではブラウザのローカルストレージに保存されます。

ブラウザのデータを削除すると保存された記録も削除されます。

公開リポジトリに追加したファイルは、トップページからリンクしていなくても閲覧できる可能性があります。

そのため、

- APIキー
- パスワード
- 個人情報
- 未公開にしたい作品やデータ

などはリポジトリに追加しない方針です。
