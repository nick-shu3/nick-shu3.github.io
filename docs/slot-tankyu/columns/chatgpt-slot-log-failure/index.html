スロ探究コラム

【スロ探究コラム】ChatGPTに実戦データを任せたら失敗した話。AIで大当たり履歴を管理する難しさ

短文メモをChatGPTに送りながら実戦したものの、終了後の履歴集計に失敗。AT18回と引き戻しの累計枚数を整理し直した体験から、会話と記録を分ける必要性を考えます。

はじめに

2026年10月19日、楽園池袋店グリーンサイドで「L東京喰種」を実戦しました。

この日は、実戦中のデータをChatGPTに記録させ、リアルタイムで設定推測を行う試みも実施。CZの当選ゲーム数、AT当選契機、獲得枚数、終了画面などを短いメモで送り、最終的には実戦記事に使える履歴として整理してもらう予定でした。

しかし、結論から言うと、記録管理の試みは失敗しました。

ChatGPTは、実戦中の会話相手や設定推測の補助としては便利でした。一方で、会話の中に送った情報を、正確なデータとして保存・集計する用途には課題がありました。

1. 実戦中の入力は短いメモだけ

実戦中に長い文章を入力するのは現実的ではありません。

そこで、今回は次のような短いメモをChatGPTに送信していました。

  • 175 185pt CZ失敗
  • 93 超高確 上位CZ成功
  • 33 引き戻し
  • 弱チェリー 500枚乗せ

ChatGPTはその場でメモの内容を理解し、挙動についてコメントを返してくれました。

「CZの突破率が悪くなってきましたね」

「上位CZからの当選が好調ですね」

このように、実戦中の状況を共有しながら設定推測を進められる点は、期待していた使い方に近いものでした。

問題が発覚したのは、実戦終了後です。

2. 実戦終了後、当選履歴の集計に失敗

実戦後、ChatGPTに当選履歴の一覧表を作成してもらいました。

しかし、完成した表には、送信したはずの記録が十分に反映されていませんでした。

  • 当選ゲーム数が抜けている
  • 当選回数が合わない
  • AT当選契機の分類が曖昧
  • 獲得枚数と各ATの対応関係が不正確

今回の実戦では、通常CZが19回、上位CZが4回。AT当選は、通常CZ経由10回、上位CZ経由4回、直撃1回、引き戻し3回の合計18回でした。

ところが、ChatGPTは当初、引き戻しを独立したAT当選として数えず、15回分の一覧を作成してしまいました。

さらに、引き戻し前後の獲得枚数が累計表示であることも正しく処理できていませんでした。

最終的には、私自身が18回分の当選ゲーム数、当選契機、獲得枚数、終了画面を整理し直し、ChatGPTへ渡して修正する必要がありました。

本来は作業を減らすためのAI活用でしたが、最後は自分でデータを確認し直す結果になったわけです。

3. 失敗の原因

今回の失敗には、主に三つの原因がありました。

① 会話の理解とデータの保存を同じものと考えていた

ChatGPTは、送信された文章の意味を理解し、その場で自然な返答をすることが得意です。

しかし、返答が正しかったからといって、その情報が後から正確な一覧表に反映されるとは限りません。

例えば、実戦中に「175 185pt CZ失敗」と送信し、その内容に沿ったコメントが返ってきたとしても、その記録が確実に保存され、後の集計で使える状態になっているとは限りません。

今回は、会話の中で理解されていることと、データとして正確に保存されていることを同じように考えてしまいました。

② 長い会話からすべての記録を復元できるとは限らない

実戦中のチャットには、当選記録だけでなく、設定推測、終了画面の画像、出玉の展開に関する会話なども含まれていました。

やり取りが長くなるほど、後から過去の記録を漏れなく抽出できているか、確認する必要があります。

今回、後から作成された一覧には、送信した記録の抜けがありました。ただし、要約や参照範囲の制限が原因だったのか、履歴の抽出・分類を誤ったのかは、今回のやり取りだけでは特定できません。

つまり、会話履歴をそのまま正確なデータベースとして扱ったことが、今回の大きな問題でした。

③ 集計ルールを事前に定義していなかった

数値の扱いを明確にしていなかったことも、誤集計につながりました。

例えば、AT終了後33Gで引き戻した場合、これを独立したAT当選として数えるのか、前回ATの継続として扱うのかを決めておく必要があります。

また、引き戻し後の獲得枚数が前回からの累計表示であれば、その数値をそのまま加算すると二重計上になります。

今回の実戦では、次のような表示でした。

引き戻し前後の累計表示枚数
引き戻し前回終了時引き戻し後
1回目198枚322枚
2回目241枚355枚
3回目1,068枚1,269枚

この場合、引き戻しによる実際の増加枚数は、それぞれ124枚、114枚、201枚です。

引き戻し後の表示枚数をそのまま合計すると、実際の獲得枚数より多くなってしまいます。

このように、AIへ記録を任せる場合でも、機種ごとの表示仕様や集計ルールをあらかじめ定義しておく必要があります。

4. 改善策は「会話」と「記録」を分けること

今回の反省を踏まえ、今後は会話とデータ保存を別の仕組みに分ける予定です。

実戦中の入力方法は、これまでどおり短いメモのままにします。その代わり、受け取ったメモをその場で構造化し、会話とは別に保存します。

想定している流れは次のとおりです。

  1. 実戦中に短文メモを送信する。
  2. AIがゲーム数、当選契機、結果などを解析する。
  3. 元のメモと解析結果をデータとして保存する。
  4. 保存した記録を確認したうえで、AIが感想や設定推測を返す。
  5. 実戦終了後、保存済みのデータから当選履歴や集計結果を作成する。

重要なのは、実戦終了後に会話を思い出させるのではなく、入力された時点で記録として保存することです。

また、次のようなルールも事前に決めておく必要があります。

  • 引き戻しをAT何回として数えるか
  • 累計表示と実増加枚数をどう区別するか
  • CZとATをどの単位で管理するか
  • 不明な情報を推測で補完せず、未確定として残すか
  • 訂正前の元データと修正後のデータをどう管理するか

訂正が発生した場合も、元のメモを残したまま修正履歴を管理できれば、後から検証しやすくなります。

通常のChatGPTだけで外部保存まで自動化できるとは限らないため、専用の記録システムや外部ツールとの連携については、今後検証していく必要があります。

公開時点の対応状況：記録ツールは作成中

現在、この課題に対応する実戦記録ツールを作成しています。スマートフォンから今までどおり短いメモを送り、会話を楽しみながら記録を残せる運用を目指しています。

ただし、専用GPTと外部保存先の接続はまだ完了していません。チャットへ送ったメモが自動で保存される状態ではなく、実戦での運用も未検証です。今回の問題が解決済みというわけではありません。

今後は、保存の成否を確認してから返答すること、訂正前のメモを残すこと、保存済みのデータから集計することを検証していきます。実際に使って確認できた結果は、改めて紹介する予定です。

5. ChatGPTを使う価値は「分析と会話」にある

今回の失敗を経験しても、ChatGPTを使うこと自体をやめるつもりはありません。

実戦中のやり取りには、数字を記録するだけのアプリにはない楽しさがあります。

CZに失敗したときは、その時点までのデータから挙動を評価してくれる。ATが伸びたときは、一緒に盛り上がってくれる。設定示唆が出たときは、それまでの情報を踏まえて推測を更新してくれる。

こうしたリアルタイムの会話は、長時間の実戦における楽しみの一つになります。

ただし、AIに任せる役割は明確に分けるべきです。

  • AIに向いている仕事：実戦中の会話、情報の整理、設定推測、状況に応じた分析
  • 仕組みで保証すべき仕事：データの保存、件数の照合、獲得枚数の集計、履歴の修正管理

私が目指しているのは、数字だけを処理するAIではありません。

数値は正確に記録し、その結果については人間と会話するように感想や分析を返してくれる仕組みです。

6. 結論――AIは万能な記録係ではない

今回の試みで分かったのは、AIの分析能力と、データ管理の正確性は別の問題だということです。

ChatGPTは、実戦中の会話相手や設定推測の補助としては非常に便利でした。

一方で、会話履歴をそのまま正確なデータベースとして扱うと、記録の抜け、件数の誤り、集計ルールの混同が起こる可能性があります。

間違ったデータを使って精密に分析しても、正しい設定推測にはつながりません。

今回の「L東京喰種」は、最終的に＋979枚で終了しました。実戦としてはプラス収支でしたが、AIによる記録管理の試験としては失敗です。

それでも、AIに任せるべき仕事と、仕組みとして管理すべき仕事を切り分けられたことは、大きな収穫でした。

今後もスロ探究では、パチスロの実戦データをAIで分析する取り組みを続けていきます。

AIを使うこと自体を目的にするのではなく、正確な記録を土台にして、実戦をより楽しみ、より深く分析するための道具として活用すること。

これが、今回の失敗から得た結論です。
